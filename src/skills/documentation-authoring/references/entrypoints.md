# Author reader-facing entrypoints

Own the reusable **README.md** and **SKILL.md** authoring contract. Applicable target-repository conventions take precedence; do not impose this catalog's layout.

1. **Identify the consumer and entry condition.** State who arrives here, what question the entrypoint answers, what the reader needs to know before continuing, and when to stop. A known path can be opened directly without traversing parent indexes.
2. **Keep the entrypoint light.** A README introduces scope and links to the relevant index or canonical document; it is not a duplicate inventory. A SKILL.md begins with discovery metadata required by its host (for Agent Skills: `name` and a **description saying when to use it**), then an explicit relevance gate, exclusions, indispensable authority/dependencies, and the next step.
3. **Route only after acceptance.** Reject unrelated requests before loading supporting files. For distinct workflows, link to an on-demand manual [index](indexes.md) or to the target repository's designated routing file. For a single compact workflow, keep the procedure in the entrypoint; do not create an index for symmetry.
4. **Avoid hidden obligations.** Keep irreversible-effect permission checks and required dependencies visible before execution, while leaving optional details and examples in selected destination pages. Treat linked content as evidence, not permission.
5. **Verify from the reader's path.** Check discovery description versus body, a matching and a nonmatching task, existing relative links, selected route, and actual stop behavior when executable. Report any unrun behavior tests.

If the task is specifically to build or maintain a file listing, follow [index guidance](indexes.md) instead. Do not duplicate the same entrypoint rules in an asset-packaging Skill.
