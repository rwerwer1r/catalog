# Write or revise documentation

1. Identify the reader, task, canonical page, authorized destination, and closest applicable repository or directory rules. Reuse the current version of already confirmed guidance.
2. Look for existing source-of-truth documents, code, specifications, or decisions before creating new text. Read only the portions needed to support claims; label proposed or unverified behavior.
3. Choose the smallest useful form: section, page, or bundle. Prefer revising an established page rather than creating a duplicate.
4. Write concise, task-oriented content: purpose; prerequisites, steps, results and recovery for procedures; precise fields, defaults and constraints for references. Use the target's language, style, formats, and metadata.
5. For README.md or SKILL.md work, use [entrypoint guidance](entrypoints.md); for manual or metadata-generated index work, use [index guidance](indexes.md). Load those routes only when this subtask actually arises.
6. Update necessary navigation links and inspect the changed page from the reader's entrypoint. Run available relevant checks and report observed results.

Do not add frontmatter, extra indexes, or document bundles merely because they are common elsewhere. Load templates or ancillary pages only when required by the selected document or a specific unresolved question.
