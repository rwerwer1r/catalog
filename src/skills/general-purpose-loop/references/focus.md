# Resolve a narrow subproblem

Use only for a material separable subproblem whose benefit exceeds its context and coordination cost; this route is optional.

1. Define a child question that is a **strict subset** of the active parent scope, with a specific result that could change the parent's evidence, plan, or acceptance.
2. Inherit or narrow all parent exclusions, approvals, safety constraints, evidence standards, and the **same cycle counter and ceiling**. Never create a new run, independent budget, or broader authority for the child.
3. Load only context needed for the narrower question. Apply the appropriate specialized workflow if useful; otherwise work directly. Complete the same investigate–plan–work–review discipline proportionately.
4. Return only the material result, evidence, unresolved limits, and changed parent prerequisites; recheck the parent plan before resuming affected work.

Prefer one distinct verification lens over a child loop when the question is merely another perspective. Do not manufacture parallel agents or claim independent review without actual separation. If the child cannot progress within the inherited bounds, return a blocker; never widen scope by nesting.
