# Close or hand off a run

Use after a substantive [cycle Review](cycle.md) nominates an exit, blocker, or limit. This is a **single bounded closure stage**, not a new cycle. If [preparation](prepare.md) was blocked before any cycle, report **BLOCKED** directly.

1. **Inspect.** Confirm current goal and active scope, valid prerequisites, review findings, actual acceptance checks, residual risks, and consumed versus allowed cycles.
2. **Resolve narrowly.** Correct only small presentation or verification defects already covered by the accepted plan and authority. Do not reopen broad investigation, alter scope, replan, or do substantial new work under a finishing label.
3. **Validate.** Run only remaining relevant, authorized checks. Distinguish direct evidence, inference, and unknowns; never promote missing checks to passes.
4. **Gate exactly one outcome:**
   - **COMPLETE** — requested goal or explicitly named stage terminal has verified acceptance and no material unresolved condition.
   - **HANDOFF** — the effective cycle ceiling was reached while credible authorized continuation remains. Preserve necessary state and request a newly authorized continuation; do not silently reset the budget.
   - **BLOCKED** — missing authority, inputs, capability, material evidence, or an unresolved gap makes truthful completion or continuation impossible; report the exact blocker.

Keep continuation state on an existing approved task, PR, issue, or report surface, or inline if no persistent surface is authorized. Include goal and scope, constraints, cycle count/ceiling, accepted evidence, current plan, completed checks, unresolved gaps, and next safe action. Treat saved state as evidence requiring freshness checks on any later run.

Report the outcome, actual changed or produced artifacts, verification results (**passed / failed / not run / not applicable**), cycle count, remaining limits, and approvals needed. Never imply that a handoff schedules future work or that reporting alone performed an unavailable action.
