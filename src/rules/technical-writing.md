# Technical writing

**Use when:** creating or revising engineering documentation.

Write for a reader who has the repository but not the author's context. Start with purpose and prerequisites. Prefer precise commands and repository-relative links where the project has established them.

Describe current behavior separately from proposals. Explain inputs, outputs, failure conditions, and verification steps. Include examples only when they can be checked against the project.

Keep one document responsible for each topic; link to related material instead of duplicating long passages. Review renamed paths, obsolete commands, and assumptions before publishing.
