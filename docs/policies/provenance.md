# Provenance and licensing policy

## Source ownership

Keep maintainable reusable assets in `src/`. For every imported or adapted external resource, determine the source, applicable license or terms, and whether copying or redistribution is permitted **before** publication. A public URL alone is not permission to remove attribution.

## Attribution and notices

Preserve required copyright, license, and permission notices for reused material. Store notices in an appropriate reviewed location and keep them associated with the affected material. If obligations conflict with the desired repository design, do not copy the asset; develop an independent implementation or seek authorization.

## Original work and references

Prefer original, task-scoped documentation when an external system is only a conceptual reference. Distinguish original content from direct adaptations and external dependencies. Do not paste personal instructions, account configuration, proprietary code or vendor-generated projections into a reusable source tree.

## Review and migration

Review provenance whenever adding code, prompts, datasets, examples, or documentation from another repository. When replacing or retiring an asset, preserve obligations that apply to surviving copied material and historical redistribution. Do not claim that deleting a file erases published Git history.
