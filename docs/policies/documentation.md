# Documentation policy

## Canonical ownership

Use one authoritative location for each instruction: `docs/policies/` for obligations, `docs/development/` for implementation guidance, `docs/agents/` for agent workflows and harnessing, and `src/` for reusable assets. Link to canonical text instead of copying policies into multiple documents.

## Authoring requirements

- Use English in accordance with [language policy](language.md).
- Start with a descriptive heading and state scope and prerequisites.
- Document current observed behavior separately from future proposals.
- Use repository-relative links for local material and stable entrypoints for external references.
- Record limitations, unsafe assumptions and unverified claims explicitly.
- Update indexes when adding, moving or removing a document.

## Maintenance

Treat stale commands, obsolete paths, broken links and ambiguous ownership as defects. Keep names stable where possible, and repair inbound links during moves. Do not claim automated document lint or agent behavior checks that have not run.
